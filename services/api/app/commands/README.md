# Синтетическое заполнение БД

Канонический путь из корня проекта:

```sh
SYNTHETIC_PASSWORD='<не менее 12 символов>' bash demo-reset.sh --purge
```

Скрипт удаляет **проектный Compose volume PostgreSQL**, применяет миграции до `0011`, импортирует 45 **фиксированных** вопросных форм в `taxonomy_question_forms`, добавляет 30 синтетических кандидатов и 5 работодателей с запросами. Для офлайн-анализа сохраняются большие fixtures 1000/50: `tests/fixtures/taxonomy/{candidates.v1.jsonl,needs.v1.json,manifest.v1.json}`. В них есть латентные уровни навыков для будущей симуляции; в БД не создаются фиктивно подтверждённые квалификации.

Для уже пустой БД `fsp` после миграций допустима отдельная команда:

```sh
SYNTHETIC_PASSWORD='<не менее 12 символов>' docker compose -f infra/docker-compose.yml run --rm \
  -e SYNTHETIC_PASSWORD -e CONFIRM_SYNTHETIC_RESET=RESET_FSP_DEMO_ONLY api \
  python -m app.commands.populate_taxonomy_demo_db
```

Она отказывается работать при любом существующем доменном содержимом и не сбрасывает БД сама. Импорт вопросного банка идемпотентен и отказывается перезаписывать расходящиеся формы. `seed_demo.py` и его старые фикстуры оставлены только для регрессионных тестов первоначального MVP, а не для нового демо-сброса.
