# Роли и пользовательские сценарии — недельный MVP

## Роли

| Роль | Делает в демонстрации | Не может |
|---|---|---|
| Кандидат | регистрация/согласия, профиль, тест/категория, тестовый статус ФСП, решение по приглашению | видеть других кандидатов; раскрывать контакты без accept |
| Работодатель | компания, потребность, подборка/причины, предложение с зарплатой, статусы | видеть ПДн/сырые ответы до accept; принимать решение за кандидата |
| Администратор демо | тестовые данные/шаблоны, сброс, отчёт валидации | менять результат без аудита |

## Сценарии P0 — только они обязательны

### UC-C01 — Онбординг кандидата и категория

1. Регистрируется, подтверждает email, даёт два согласия.
2. Заполняет профиль и выбирает специализацию/заявленный грейд.
3. Проходит вариант теста; сервер синхронно оценивает рубрику.
4. Видит подтверждённую категорию, сильные стороны и подсказку о повторном тестировании.

**DoD:** unverified/unpublished profile отсутствует в matching; failed test не понижает grade; попытка/результат принадлежат только candidate.

### UC-C02 — Тестовая ФСП / отсутствие истории

Кандидат вводит тестовый ID ФСП или выбирает демонстрационный профиль. Сервер возвращает агрегат достижений либо `no_history`.

**DoD:** no_history не выглядит ошибкой и не исключает candidate; никаких real FSP integration claims.

### UC-E01 — Потребность → ранжированная подборка

Работодатель создаёт компанию и потребность (специализация, минимальный/целевой грейд, навыки). Сервер синхронно сохраняет неизменяемый снимок рекомендаций: категория/навыки/тест/оценка ФСП + 2–3 причины.

**DoD:** top-3 соответствует labelled seed; filters do not reveal PII; reset restores base list.

### UC-E02 — Приглашение с зарплатой → контролируемые контакты

Работодатель выбирает кандидата и отправляет предложение с компанией, описанием, способом связи и диапазоном зарплаты в RUB. Кандидат видит условия, просматривает и принимает/отклоняет их. Автомат состояний сервера контролирует `sent → viewed → accepted|declined`.

**DoD:** invalid salary rejects; pre-accept/decline API response lacks email/phone; after accept only originating employer sees them; audit exists.

## P1 — только после готовности P0

- Уведомления Mailpit о подтверждении и приглашении.
- Загрузка CV только в локальное/приватное хранилище; без разбора.
- Улучшенные фильтры и полировка интерфейса.

## Обязательные сценарии до финальной сдачи

### UC-C03 — История и повторное тестирование

Кандидат видит историю опросов/тестов/category. После недостаточного результата сервис предлагает тестирование на уровень ниже, после уверенного — на уровень выше; дата следующей попытки ограничена cooldown. Грейд не снижается автоматически.

### UC-C04 — Стандартизированный PDF-профиль

Кандидат скачивает сгенерированный профиль из заполненных и разрешённых им полей. PDF не зависит от тяжёлого PDF-parsing и не раскрывается работодателю автоматически.

### UC-E03 — Полный банк и уточнение выдачи

Работодатель ищет по специализации, грейду, category, стеку и наличию достижений ФСП. Фильтры применяются поверх неизменяемой базовой подборки; «Сбросить» возвращает исходный snapshot. Контакты остаются маскированными.

## Явно не реализуется за неделю

Вакансии/отклики, регулярные задания, реальные ФСП/Keycloak/ATS, Redis Streams/отложенные состояния, мобильная версия, антифрод, LLM-тесты.

## Сценарий приёмки демонстрации

1. Кандидат завершает профиль/тест и получает категорию.
2. Работодатель создаёт потребность и видит ожидаемую подборку/причины.
3. Работодатель отправляет предложение с зарплатой.
4. Кандидат принимает его во второй сессии.
5. Работодатель видит контакт; второй работодатель остаётся без доступа.
